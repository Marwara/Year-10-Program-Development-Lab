The Program Development Lifecycle

A hands-on workbook: follow one real problem — a cinema ticket calculator — through analysis, design, coding and testing.

1. Key vocabulary

Open every card. The Studio below uses these words without re-explaining them.

Analysis

Finding out exactly what the program must do: the problem, the inputs, processes and outputs, and the requirements. Uses abstraction and decomposition.

Design

Planning the solution before writing it, using structure charts, flowcharts and pseudocode.

Coding

Writing the program in a programming language from the design, testing each part as it is written (iterative testing).

Testing

Running the program with test data and comparing the actual result with the expected result, to find and fix errors.

Decomposition

Breaking a big problem into smaller, easier sub-problems, each of which can become a module.

Abstraction

Removing unnecessary detail so only what matters to the problem remains.

Pseudocode

Structured, language-independent steps using keywords like INPUT, IF, OUTPUT, so the logic can be checked before coding.

Flowchart

A diagram of the steps and decisions in order. Rounded box = start/end, parallelogram = input/output, rectangle = process, diamond = decision.

Structure chart

A top-down diagram showing how a program is decomposed into modules and sub-modules, with the main program at the top.

Test data

Normal = valid and typical. Extreme = the largest/smallest valid values. Boundary = values at the edge of valid/invalid. Abnormal = invalid, must be rejected.

4. Structured questions


(a) [2] State what is meant by decomposition and give one benefit.
Model answer
Breaking a problem into smaller sub-problems (modules). Benefit: each part is easier to understand, design, code and test, and different people can work on different modules.


(b) [3] A program asks for a mark from 0 to 100. Give one example each of normal, boundary and abnormal test data and say what should happen.
Model answer
Normal: 55 accepted. Boundary/extreme: 0 or 100 accepted (and 101 or -1 just outside, rejected). Abnormal: "abc" or 500 rejected with an error message.


(c) [3] Describe two differences between a flowchart and pseudocode.
Model answer
A flowchart uses standard symbols and arrows to show the flow visually; pseudocode uses text keywords. Pseudocode is closer to real code and easier to convert; a flowchart makes the order of decisions easier to see at a glance.
